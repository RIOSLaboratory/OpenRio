# Standalone VCS + Verdi FSDB flow

This directory is a **separate VCS entry point**. It does not modify or invoke the
existing Verilator flow:

```text
verification/or_cosim/tools/verilator_cosim.sh
verification/or_cosim/tools/regress.sh
```

It only reads the existing testbench sources, filelists, and DPI adapter:

```text
verification/or_cosim/cfg/filelist/*
verification/or_cosim/dpi/isa_dpi_pkg.sv
verification/or_cosim/dpi/isa_dpi_wrapper.cc
verification/or_cosim/tb/*
```

Keeping the VCS script here means the Verilator/ST environment can stay frozen while
the VCS flow is developed and tested independently.

Both engines are also reachable through one front end, which is what the
regression guide now documents:

```bash
verification/tools/or_cosim.sh build   --engine vcs --tag vcs1
verification/tools/or_cosim.sh regress --engine vcs --tag vcs1 -j 16
verification/tools/or_cosim.sh compare --tag vcs1        # diff vs the Verilator run
```

The raw `make` targets below stay valid; the front end only forwards to them.

The detailed, current step-by-step record (including the dev2 paths already
confirmed and the issues seen so far) is in
[`VCS_WAVEFORM_STEPS.md`](VCS_WAVEFORM_STEPS.md).

## Prerequisites

- VCS (tested target: the site's `VCS_HOME`)
- Verdi with the VCS PLI (`novas.tab` and `pli.a`)
- `ISA_MODEL_ROOT` in **either** of two layouts, detected automatically:
  ```text
  build tree   : $ISA_MODEL_ROOT/src/libs/IsaApi.h + $ISA_MODEL_ROOT/build/lib_ISA_api.so
  install tree : $ISA_MODEL_ROOT/include/IsaApi.h  + $ISA_MODEL_ROOT/lib/lib_ISA_api.so
  ```
- A C++20-capable compiler (`gcc14`), used for both the ISA model and the DPI
  wrapper, so they share one `libstdc++`

### Host compatibility (learned the hard way)

- The ISA model `.so` must be **built on the same host** as the simulation.
  A library built on a newer glibc cannot be loaded by an older one: the dev2
  copy required `GLIBC_2.38`, while cad21 runs glibc 2.17.
- VCS `T-2022.06-SP2` itself does **not** run on Ubuntu 22.04 (glibc 2.35):
  `vcs1` fails with `GLIBC_PRIVATE not found`. cad21 (CentOS 7) works.
- Verify a freshly built model with:
  ```bash
  objdump -T build/lib_ISA_api.so | grep -oE 'GLIBC_[0-9]+(\.[0-9]+)+' | sort -Vu | tail -1
  ```
  The answer must be `GLIBC_2.17` on cad21.
- The internal `function-model` tree keeps its BE metadata in
  `include/ext/IsaApiExt_BE.h` and is **not** interchangeable with this wrapper.
  Use its `env.sh` for the toolchain only.

Set the environment:

```bash
cp env.sh.example env.sh
# edit env.sh
source env.sh
```

## First build

```bash
cd verification/vcs_cosim

make check                     # validates VCS/Verdi/ISA model paths
make build TAG=vcs1 DUT_KIND=rtl_full
```

The build outputs:

```text
verification/or_cosim/sim/vcs_vcs1/build/rtl_full/simv
verification/or_cosim/sim/vcs_vcs1/build/rtl_full/dpi/libisa_dpi.so
verification/or_cosim/sim/vcs_vcs1/build/rtl_full/compile.log
```

They sit next to the Verilator trees (`or_cosim/sim/verilator_<tag>/`) so the two
engines can be compared file by file. Set `VCS_WORK_ROOT` to move them elsewhere
(a scratch disk, a test rig).

`WAVE` is deliberately **not** part of this path: every `simv` is compiled with
FSDB support, so a single build serves both waveform and silent runs.

## Run one case and generate FSDB

```bash
make fsdb \
  TAG=vcs1 \
  DUT_KIND=rtl_full \
  TC=$ISA_MODEL_ROOT/isa_case/rv64ui/rv64ui-p-add.riscv
```

Outputs:

```text
verification/or_cosim/sim/vcs_vcs1/log/rtl_full/rv64ui-p-add_1/sim.log
verification/or_cosim/sim/vcs_vcs1/log/rtl_full/rv64ui-p-add_1/rv64ui-p-add.fsdb
```

Open it:

```bash
bash "$VERDI_HOME/bin/verdi" -ssf \
  verification/or_cosim/sim/vcs_vcs1/log/rtl_full/rv64ui-p-add_1/rv64ui-p-add.fsdb &
```

In Verdi:

- Scope: `be_tb_top`
- Expand `u_backend`, `u_fe`, `u_cache`, `u_icache`
- `Signal -> Get Signals` to add signals

## FSDB is generated by VCS directly

The testbench has the FSDB path behind `VCS_FSDB`, and the waveform itself is a
**runtime** choice inside that block:

```systemverilog
`ifdef VCS_FSDB
  initial begin : fsdb_dump
    if (!$value$plusargs("WAVE=%s", vcs_wave_mode)) vcs_wave_mode = "fsdb";
    if (vcs_wave_mode == "fsdb") begin
      if (!$value$plusargs("FSDB_FILE=%s", fsdb_file)) fsdb_file = "be_tb_top.fsdb";
      $fsdbDumpfile(fsdb_file);
      $fsdbDumpvars(0, be_tb_top, "+all");
      $fsdbDumpMDA();
    end
  end
`endif
```

The Makefile therefore always adds at **compile** time:

```text
+define+VCS_FSDB
-P $(FSDB_PLI_DIR)/novas.tab $(FSDB_PLI_DIR)/pli.a
```

and selects the dump at **run** time:

```text
+WAVE=fsdb  +FSDB_FILE=<case>.fsdb     # waveform
+WAVE=none                             # silent, same simv
```

`+all` also records memories and packed arrays, and `$fsdbDumpMDA()` handles
multi-dimensional arrays; without them the ROB, store buffer and cache arrays
show up empty in Verdi.

This is a native VCS FSDB dump, not Verilator VCD + `vcd2fsdb`.

## Important differences from the Verilator flow

- `isa_dpi_pkg.sv` is passed **before** `common.f`; `orbe_predictor_pkg` imports it.
- `tb/agents/be/be_bfm.sv` is filtered out of the tb filelist for every
  `DUT_KIND` except `agent`. It is the RTL stand-in used only by the agent
  configuration, `be_tb_top.sv` never instantiates it under the `rtl_*` kinds,
  and VCS rejects its parameterized interface port (`ob_cosim_if #(...)` in an
  ANSI port list) with `Error-[SE] Syntax error ... token is '#'`. The filter is
  written to `sim/filelist/tb_<DUT_KIND>.f`, so the tracked `tb.f` shared with
  the Verilator flow is never modified.
- DPI is built as `libisa_dpi.so` and loaded with `-sv_lib`; the Verilator flow
  compiles `isa_dpi_wrapper.cc` into the executable instead.
- `WAVE` is a runtime plusarg here, not a build namespace: one `simv` covers
  `WAVE=none` and `WAVE=fsdb`. The Verilator flow still needs a separate build
  per `TRACE` value.
- `-Mupdate` keeps the VCS `-Mdir` database, so a TB edit recompiles only the
  stale compilation units.
- The DPI library directory and the ISA model library directory must both be on
  `LD_LIBRARY_PATH` at VCS link time **and** at run time, because `-sv_lib` is a
  `dlopen`. `LD_LIBRARY_PATH` also needs the gcc14 `lib64` so `simv` finds the
  matching `libstdc++`.
- Simulation output is captured with `tee` under `bash -o pipefail`; a VCS `-l`
  file only records simulator-managed output and would drop DPI `printf`.
- Batch regression is `regress.sh` in this directory (the VCS twin of
  `or_cosim/tools/regress.sh`): same arguments, same stdout lines, same
  `results.txt`/`summary.txt` format, so the two engines can be diffed with
  `tools/or_cosim.sh compare --tag <tag>`.

## Batch regression

```bash
source env.sh
./regress.sh rtl_full vcs1 16                      # 239 ISA cases
./regress.sh rtl_full vcs1 16 ../../or_cosim/cfg/cases/cases_embench.list
```

Output:

```text
verification/or_cosim/sim/vcs_vcs1/regress/rtl_full/cases_239/results.txt
verification/or_cosim/sim/vcs_vcs1/regress/rtl_full/cases_239/summary.txt
```

The batch builds once (an up-to-date `simv` costs a fraction of a second), then
runs one `make run` per case under `xargs -P`. Judgement is identical to the
Verilator batch: exit code 0, no failure keyword, and `is_good=1` in `sim.log`.
Exit code is 0 only when every case passes.

## Portability rules (VCS front end is older than Verilator 5.050)

Three constructs compile under Verilator but are rejected here. Keep the shared
TB free of them so one source tree serves both engines:

| Construct | VCS error | Fix |
| --- | --- | --- |
| parameterized interface as a module port | `Error-[SE] Syntax error ... token is '#'` | non-parameterized interface or a virtual interface handle |
| declaration after use in the same scope | `Error-[IND] ... has not been declared yet` | declare first |
| member of a function-call result (`f(x).field`) | `Error-[SV-FNYI] Feature not yet implemented` | assign to a temporary, then read `.field` |

## Site-specific flags

If the site's VCS needs extra options, pass them through:

```bash
make build TAG=vcs1 VCS_EXTRA_FLAGS="-lca -notice"
```

`-debug_access+all` and `-kdb` are already in the default VCS flags for FSDB.
